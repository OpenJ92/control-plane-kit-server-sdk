The Docker build context omits Git metadata, workflows, virtual environments,
Python caches and build/distribution output. It also excludes test_support/*,
then re-includes the verification and FastAPI installed-dependency probes that
the [Dockerfile](Dockerfile.md) copies into its test stage. The broader support
suite reaches gate containers through read-only mounts instead.

These are build-context patterns, independent of [.gitignore](.gitignore.md).
They neither remove already tracked files nor establish a complete secret
exclusion policy. A new copied support file requires a compatible context rule;
otherwise Docker cannot satisfy COPY. Conversely, broadening context includes
more local material even if the Dockerfile never installs it.

[Gate-contract tests](test_support/tests/test_gate_contract.py.md) check the
required pattern set and Dockerfile shape. That source-level check does not
execute Docker's pattern engine or prove the contents of a built image.
