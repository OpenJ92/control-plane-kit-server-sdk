Optional verification setup consumes the pure Core receiver V2 configuration at pin 1f28d009. `load_wrapper_configuration` opens the absolute environment-selected final path with no-follow/nonblocking flags, checks the opened descriptor is a regular 0444 file, reads at most the Core byte ceiling plus one, rejects observed metadata changes, and decodes through the shared codec. It closes the descriptor on every outcome and returns fixed detached ordinary errors. Parent-directory trust and delivery integrity belong to composition; read-only mode is not producer authentication. There is no process-global cache, watcher, credential creation or authority store.

Trusted supplied values pass through the same bounded codec. Setup constructs existing exact-purpose snapshots, holders and Ed25519 verifiers with the configured issuer, derived target audience and default integer wall clock. Existing health dispatch owns authentication and closed outcome enforcement. Optional no-argument synchronous callbacks must correspond to declared health kinds. Default liveness reports responsiveness; readiness reports observed serving, optionally refined by a product callback. No database or business readiness is inferred.

A per-instance lock protects stopped/starting/serving/stopping phases and an invocation epoch. Shutdown wins over late serving hooks. Optional readiness executes outside the lock, and its epoch/phase is checked again before returning, preventing a late healthy result across stop/restart. Concurrent host lifespans/loops are refused. This is process-local observation, not draining, durable history, native supervision or recovery. Host adapters own the public lifecycle hooks. Base SDK imports do not import this optional module.
