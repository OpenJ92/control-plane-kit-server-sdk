This optional verification-extra module captures frozen trusted target/runtime/V2 declaration, one exact health verifier and two named synchronous no-argument callbacks. Callback presence must equal declared health kinds. Inspectable signature binding and async-function rejection happen without invoking callbacks; these are trusted application callables, not an arbitrary plugin/URL/operation registry. Configuration failures are fixed and cause/context-free. Repr excludes local references, verifier and callbacks.

Every read calls the accepted verifier with captured independent context and actual kind before selecting exactly one callback. Exact Core NodeHealthReadOutcome becomes NodeHealthReadResult derived from that admitted request/declaration. Ordinary exceptions/wrong returns become fixed nonsemantic dispatch errors; BaseException propagates. Accidentally returned native coroutines are closed without executing them so their warning does not expose implementation details. No async callback execution is supported.

The module imports no web framework and is not exported/imported by the base root. The verification-extra installed probe checks this boundary. No callback credential/context argument, health cache, replay ledger, provider adapter, durable truth, lifecycle or timeout mechanism is introduced. A repeated valid read may call again with the same observation identity. Callbacks own bounded dependency operations; HTTP framing and off-loop placement belong to the FastAPI adapter.
